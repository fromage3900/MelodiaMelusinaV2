# First $20 — Revenue Proof Gate

**Objective:** prove that existing WebGL capability can generate the first externally funded inference budget without becoming a second full-time project.

This gate is deliberately tiny. Do not optimize for a brand launch, follower count, or marketplace catalog yet.

## Definition of success

Success requires all of the following:

1. one real prospect or buyer accepts a bounded WebGL deliverable;
2. payment is actually received;
3. inference/platform costs are recorded;
4. at least CAD $20 equivalent is designated to `EARNED_POOL`;
5. the job leaves behind one reusable generic primitive, checklist, benchmark, or template.

## Evidence we can make immediately

Create only these three proofs before outreach:

### A. Rescue proof

Take an owned Three.js scene and record:

- initial payload / load behavior;
- initial frame-rate or obvious bottleneck;
- one bounded optimization pass;
- before/after capture;
- three bullets explaining what changed.

This sells SKU 1.

### B. Viewer proof

Use an owned/generic GLB in a clean-room viewer and capture:

- responsive orbit view;
- clean lighting/material response;
- loading state;
- mobile-width layout.

This sells SKU 2.

### C. Playable proof

Run `templates/microgame/` through a local web server and capture the complete five-object collection loop on desktop and phone-width.

This sells SKU 3 and proves the kit is executable rather than only documented.

## First outreach batch

Do not mass apply.

Find **10** current paid problems and score them using `SERVICES.md`.

Keep at most the **top 3**.

For each survivor record:

```text

DELIVERY RISK

Human approval is required before contact or proposal submission.

## Preferred first job

The ideal first win is intentionally boring:

- one broken viewer;
- one oversized GLB;
- one interaction bug;
- one basic asset viewer;
- one tiny playable promo;
- one short audio-reactive scene.

Target a problem that can be finished decisively, evidenced clearly, and handed off without ongoing support.

```

The first milestone is not revenue maximization. It is proving the loop:

```text
existing skill
→ paid problem
→ bounded delivery
→ payment
→ measured token reinvestment
→ reusable capacity increases
```

## Stop conditions

Pause this experiment if:

- it starts displacing capstone P0;
- three consecutive outreach batches produce no credible leads;
- delivery requires unrelated backend/full-stack scope;
- a prospect asks for unpaid speculative production beyond a tiny assessment;
- legal/IP ownership is unclear;
- the reusable-kit work grows faster than actual demand.
