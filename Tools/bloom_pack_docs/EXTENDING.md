# Extending Resonant Blooms (guide for a developer or an AI model picking this up)

Everything is generated by one Python file, `source/blooms.py`, run inside Blender 5.2. There is no hand-edited node
tree: change the Python, rebuild, look at renders. **Always look at the renders** — numbers alone hid several real bugs.

## Rebuild + look (the loop)

```
blender --factory-startup --background --python source/bloom_preview.py -- OUT_DIR rose peony vine
   -> OUT_DIR/<species>_side.png, <species>_top.png   (bud / half / full, Workbench, single colour)
blender --factory-startup --background --python source/pack_bloom_generator.py -- OUT_DIR
   -> the sellable pack: ResonantBlooms.blend, ResonantBlooms_Demo.blend, previews/demo_hero.png (Cycles CPU), zip
```
Run Blender in the background and read the log (`PYTHONUNBUFFERED=1 ... > log 2>&1`). Do not pipe through `tail`/`grep`
if you want to see progress; a hung Blender looks identical to a quiet one.
`--factory-startup` scenes contain a default 2 m cube at the origin — delete it or it fills the camera.

## Architecture

* `_G` is a tiny node DSL: `g.node(idname, **props)`, `g.m(op, a, b, c)` (Math; floats become defaults, sockets are
  linked), `g.vec(x,y,z)`, `g.maprange(v, a0, a1, b0, b1, smooth)`, `g.euler(x,y,z)`, `g.link(a, b)`.
* `_tree(name, params)` creates the group + interface. `params = [(name, socket_type, default, min, max)]`; material
  sockets use default `None`.
* `_petal(g, gin, p)` builds one solid petal (grid → set position from a width profile, spine curl, cup, ruffle →
  extrude for thickness → smooth shade). `p` = petal shape dict. It reads group inputs `Length`, `Width`, `Ruffle`,
  `Thickness`, `Growth`, so any group that has those can reuse it.
* `_whorl(...)` instances the petal on a ring (`GeometryNodeMeshLine` → set position → `InstanceOnPoints`), one whorl per
  `SPECIES[...]["counts"]` entry. Whorl k is rotated by `k * GOLDEN`; `t0[k]` is the Growth value at which it starts
  opening; `c`/`o` are closed/open tilt in degrees; `r`/`z` radius/height; `s` petal scale.
* `_build(species, name)` joins whorls + stem + stamens, writes the `GrowthCol` colour attribute, then
  `g.apply_parts` / `g.apply_materials`.
* `_vine(name)` = line → resample → sway → trim by Growth → radius taper → tube; leaves + tendrils instanced on the
  resampled points, scaled in by Growth.
* To add a **species**: add an entry to `SPECIES` (counts, r, z, s, c, o, t0, petal dict), a `build_bloom_x` function and a
  `PRODUCT` row in `pack_bloom_generator.py`. Nothing else is needed.

## Things that cost hours — read before editing

1. **Join Geometry drops `material_index`.** Parts are tagged with a FACE int attribute `part_mat`; `_G.node(
   "GeometryNodeSetMaterialIndex")` is shimmed to store that, and `apply_parts` / `apply_materials` convert it after the
   final join. Do not call `SetMaterialIndex` directly (pass `_real=True` if you truly must).
2. **GN meshes do not use the object's material slots.** Materials must come from `Set Material` (material sockets on
   the group interface). Previews without material inputs render single-colour — that is expected.
3. **Blender 5.x: you cannot write modifier input values as id-properties.** Set `interface item.default_value` on a
   *copy* of the group (`tree.copy()`), then add the modifier. See `put()` in the pack script.
4. **Math node operands:** both inputs default to 0.5. `_G.m` writes both, always.
5. **Menu inputs:** `ResampleCurve` mode is an input socket (`inputs["Mode"].default_value = "Count"`), but
   `CurveToPoints` mode is a node property (`mode="EVALUATED"`). `RandomValue` FLOAT output is `outputs[0]`.
6. **Curve radius:** `Curve to Mesh` showed a 1 m tube until the radius went on the profile circle and the taper went
   through `Curve to Mesh ▸ Scale`.
7. **Petal tips:** a width profile that hits exactly 0 with few rows gives needle spikes. Rows are packed toward both ends
   with a cosine remap; the profile is a rounded super-ellipse. Do not "simplify" this.
8. **Bowl vs saucer:** bloom silhouette is set by (a) per-whorl `r` and `z`, (b) petal `bend` / `recurve` (outward curl),
   (c) `c`/`o` tilts. Widening petals made it worse (trumpet + flat lid). Whatever you try, render side + top.
9. **EEVEE does not render usefully in `--background` here** (3-second blank frame). Use Cycles CPU for previews.
10. Material color/`Attribute` node must read colour attribute `GrowthCol` with `attribute_type="GEOMETRY"`.

## Roadmap ideas (all optional)

* **Real bowl rose:** per-whorl petal shape (a second/third petal dict) and a curved calyx; an inner "spiral heart" of
  3 rolled petals.
* **More species** from the same recipe: camellia (rings of 8, ruffled), lotus (13 flat petals, big cup), ranunculus
  (very many small petals), tulip (6 petals, never opens), lily (6 recurved petals + stamens).
* **Musical mapping:** expose a `Mode`/scale input that picks per-whorl petal counts and tilts from scale degrees
  (Lydian = lifted, Dorian = relaxed); expose a `Root Pitch` that sets overall size (low note = big flower:
  `size ∝ sqrt(f_ref / f)`).
* **Bouquets / fields:** a scatter group that instances flowers on a surface with random Growth and Seed.
* **Wind:** vertex-animation texture or a sin(time + GrowthCol.B) bend input.
* **Game export:** `source/bake_bloom_kit.py` bakes Bud/Half/Full stages × seeds to FBX with `GrowthCol` colour +
  UV maps (these survive FBX; custom float attributes do not). Needs materials supplied through the group sockets.
* **LODs:** lower petal grid resolution (`Vertices X/Y` in `_petal`) for distant flowers; peony is 22k tris.
* **Presets:** a few colour ramps per species (blush, crimson, white, yellow, lavender) as extra materials.

## Pack contents contract

`pack_bloom_generator.py` writes `ResonantBlooms.blend` (assets), `ResonantBlooms_Demo.blend`, `previews/`, copies
`source/` and the docs, and zips the folder. Keep those names stable if the product is on sale.
