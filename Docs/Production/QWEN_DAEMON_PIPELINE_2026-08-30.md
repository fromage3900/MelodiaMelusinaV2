**Date:** 2026-08-30
**Mode:** Research and design (no model writes to .uasset)
**Lane:** `daemon` → `qwen3-coder:14b` (primary) → `qwen3:8b` (fallback)

---

## Why

Hermes cron jobs can run unsupervised overnight. A daemon lane with local models gives us:

- 24/7 read/research capability without API cost
- Spec generation (material orchestration, beatmap research, audit sweeps)
- Queue self-refill via read_review_loop
- Full logging to `Saved/Daemon/overnight_*.log`

## Pipeline

```
Cron fires → Read queue → Pick lowest priority → Route model → Execute prompt → Mark done → Log
                                                                                          ↓
                                                                              Queue < 3? → read_review_loop
                                                                                          ↓
                                                                               Generate 3 micro-tasks → Append
```

```
daemon → qwen3-coder:14b → qwen3:8b → nemotron free
```

## Guardrails

1. **Never write .uasset directly** — all material work via `materialize_*.py` scripts in editor
2. **Never certify gates without ledger** — gate evidence requires `Docs/Reports/P0_LIVE_GATE_EVIDENCE_MATRIX_*.json`
3. **Propose specs/PRs** — do not impose features, defer to owner decision
4. **Compact context when >80%** — summarize completed items, keep only active work in focus
5. **Never guess credentials or secrets** — stop and wait for user if auth needed

## Queue Self-Refill

When queue drops below 3 items:

1. Run `read_review_loop` prompt
2. Scan `Saved/Audit/*.json` for loose ends
3. Scan `Docs/Plans/*.md` for incomplete work
4. Append 3 new well-labelled micro-tasks to `Saved/Audit/overnight_queue_2026-08-30.json`
5. Re-queue the `read_review_loop` prompt itself (recurring)

Cron jobs live in Hermes config (`~/.hermes/cron.yaml` or profile equivalent). The overnight orchestrator is scheduled for unsupervised execution when no user is present.
