## Repairs made this pass (were broken, now proven green)

**R1 — `hda/ArpeggioStair_1.0.hda` was an unsmudged LFS pointer.** A 130-byte pointer
file on disk (`.git/lfs/objects/2c/42/<oid>` *did* hold the real 24,644-byte blob, so no
network fetch was needed). Houdini could not load it — Gate 2 reported
`install: OperationFailed: Couldn't add library ... to Current HIP File`.
Fixed with `git lfs checkout -- hda/ArpeggioStair_1.0.hda`, after verifying the local
blob's sha256 against the committed oid. `git status -- hda` is clean; the file is now
24,644 B and cooks at its golden `output0: 512 pts / 384 prims`.

**R2 — `Content/HDA/ArpeggioStair_1.0.hda` was the pre-promotion HDA.** 8,096 B with no
`stepCount`/`laneCount` parms on the type, while `hda/` held the 2026-10-06 promoted
rebuild (24,644 B). The registry declares the two byte-identical, so the UE-facing copy
was silently a different generation. Fixed by byte-copying `hda/` → `Content/HDA/`
(old file preserved at
`Saved/Audit/houdini_hip_convergence_20261009/quarantine/ArpeggioStair_1.0_PRE_PROMOTION_8096B.uasset-source.hda`).

**R3 — the HDA gate now passes both stages.** Before: `Gate 2 FAILED` (ArpeggioStair
could not install). After R1+R2:
```
[hda_verify] {'PASS': 3, 'WARN': 4, 'FAIL': 0} | Houdini 22.0.368 (licenseCategoryType.Apprentice)
[hda_verify] Gate 0 PASS
[hda_verify] Gate 2 PASS
```
The 4 WARNs are the pre-known OWED registry entries (builders exist, HDAs never written).

A note pinned on R1: the gate **did** catch the stub properly — four checks failed
(`has_network`: *"no Contents.gz section - empty shell / stub"*, `label_matches`,
`mirror_identical`, plus the cook install). The `globs.stub` / `hda/backup/*.hda` glob is
a *backup-drift* alarm, not the stub detector; the per-entry **`has_network`** check is,
and it fired. The only real residual gap is narrow: a stub for a HDA that is **not in
the registry** is only a WARN (`scan` rule), never a FAIL.

## Traps worth keeping in mind

- **`build_melusina_weight_lab.py` without `hou` writes a 78-byte stub over your `--out`
  path.** The old `choral_sheep_variants.hipnc` stub is what that produces. Always run it
  under `hython`; never against a path you care about with a plain `python`.
- **`Tools/*` is gitignored** (`.gitignore:~250`) with per-file allowlisting, so new files
  here need `git add -f <path>` or they silently stay untracked.
- **The `Humber_FinalYear_Prep/.../MANIFEST.json` hash pins `skiff_hero3b_v1.hip`** at
  SHA `7892AED11D...` / 188,210 bytes. If you ever re-bake that hip, update the manifest.
