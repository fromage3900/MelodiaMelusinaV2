## Verification performed

- `npm test` (`node --test --test-isolation=none`): **12/12 passing** (protocol validation, malformed/unknown-version handling, AIRI ACT marker allowlist, rate limits, relay forwarding, offline relay behavior, queue behavior).
- Node syntax checks: **PASS** for `bridge.mjs` and `relay.mjs`.
- Character-card generator: generated manifest/card/ZIP and read-back checked their JSON and exact root-file package structure.
- The repository pre-commit policy rejects ZIP files, so the verified `Melusina.airi-card.zip` is kept as a local generated artifact; the generator, JSON card, and manifest are the committed sources.
- UE 5.8 editor target build: **PASS** (`BS_GodFileEditor Win64 Development`, isolated worktree, `-MaxParallelActions=3`; UBT result `Succeeded`, 729.33 seconds). The bridge translation unit compiled and the `UnrealEditor-BS_GodFile.dll` linked. Two UE 5.8 API mismatches were fixed: `FTSTicker::FDelegateHandle` and the return-value `FJsonObject::TryGetField` API.
- Build-only local dependencies were supplied inside the worktree: Oceanology descriptor/source/matching editor binaries and Claireon descriptor/source. Their large content directories were not copied; the active checkout and editor were not modified. Existing plugin deprecation/conversion warnings remain outside this bridge change.
- Direct npm SDK installation: **BLOCKED**. `npm install --ignore-scripts --no-audit --no-fund --package-lock=false` fails with registry `E404` for `@proj-airi/better-ws@^0.12.0-beta.5`. AIRI's `server-sdk` manifest declares this as `workspace:^` in its monorepo, and the package manifest is not available from the npm registry ([server-sdk manifest](https://github.com/moeru-ai/airi/blob/main/packages/server-sdk/package.json), [better-ws manifest](https://github.com/moeru-ai/airi/blob/main/packages/better-ws/package.json)). A sparse checkout of the official AIRI workspace built `plugin-protocol`, `server-shared`, `better-ws`, and `server-sdk`; the relay authenticated and reached ready against desktop AIRI.
- Live UE → AIRI transport probe: **PASS** for standalone emission and relay forwarding. On `/Game/MelodiaIntegration/Maps/MelodiaIntegrationMap` with `-game -nullrhi -MelodiaAiriBridge`, relay health reported `airiConnected=true`, `eventsReceived=1`, `eventsForwarded=1`, `lastTx=melodia.world.location`, `intentsAccepted=0`, and `rejected=0`. The send was accepted by the AIRI SDK transport; AIRI-side visible context consumption or response was not independently observed. UE logs: `Saved/Logs/AIRI_P0_MelodiaIntegration_Standalone_20260930.log` and `Saved/Logs/AIRI_P0_MelodiaIntegration_Offline_20260930.log`.
- Offline standalone smoke: **PARTIAL**. With relay port 8765 closed, the same isolated map process remained alive at the five-second check and its log had zero fatal entries. This does not prove ordinary gameplay or PIE behavior.
- PIE and live AIRI intent return remain **NOT PROVEN**. The available Monolith controller is attached to the active canonical editor, so the proof was kept within the isolated worktree. A separate Morning-map standalone attempt crashed in the build-only Oceanology dependency at `AOceanologyLake::InitCaustics()`; it did not affect the canonical checkout. The integration map was used for the event probe instead.
